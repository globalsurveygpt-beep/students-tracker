# План работ: веб-приложение учёта посещаемости студентов

Срок: 5 дней, с 05.11.2026 по 09.11.2026 (дедлайн — 09.11.2026). План пересчитан 06.11.2026: макеты заняли больше времени, чем планировалось, запасных дней не осталось. Печатный документ пишется частями параллельно с кодом.

## 1. Зафиксированные решения

| Область | Решение |
|---|---|
| Backend | C#, ASP.NET Core 10 (.NET 10 LTS), Minimal API или контроллеры (выбрать один стиль в спеке и не смешивать) |
| ORM | EF Core 10 + Npgsql (провайдер для EF Core 10), миграции |
| БД | PostgreSQL 18 (установлен у владельца, защита на его компьютере) |
| Frontend | Статичные HTML/CSS/JS в `wwwroot`, без фреймворков, `fetch` к REST API того же origin |
| Авторизация | Cookie-аутентификация, хеш пароля через `PasswordHasher`, роли `admin` / `teacher` / `student` |
| Учётные записи | Создаёт админ: логин + временный пароль. Свободной регистрации и кодов приглашения нет |
| Студент | Только чтение своей посещаемости; права проверяются на сервере |
| Дизайн | Единый источник: `mockups/!DESIGN_TOKENS.html` (цвета, шрифты, радиусы, отступы, SVG-иконки). Две темы: светлая и тёмная (переключатель, по умолчанию системная). Desktop-first для всех экранов; кабинет студента кросс-платформенный (360, 768, 1280 px) |
| Шрифты | Локально в `wwwroot/fonts`, без CDN (защита может быть без интернета) |
| Презентация | Не нужна |

Чего не делаем (против оверинжиниринга): микросервисы, CQRS, репозитории поверх EF, SPA-фреймворки, JWT, Docker, принудительная смена пароля при первом входе.

## 3. Модель данных (предварительно, уточняется в SPEC.md)

- `users` — логин, хеш пароля, роль, активность.
- `groups` — название, год.
- `students` — ФИО, группа, ссылка на `users` (nullable, уникальная).
- `subjects` — название.
- `lessons` — дата (`date`), номер пары, предмет, группа, преподаватель.
- `attendance` — урок, студент, статус (`present` / `absent` / `excused` / `late`), примечание. Уникальность пары (урок, студент).

Заранее учтённые ошибки: даты урока как `date` без часового пояса; уникальность отметки; запрет каскадного удаления студента с историей (мягкое удаление или запрет); хеширование паролей; строка подключения вне git; воспроизводимые миграции; серверная проверка прав по роли.
